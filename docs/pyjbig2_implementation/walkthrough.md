# pyjbig2 実装完了報告 (M2 / M3 マイルストーン)

仕様書 `JBIG2_ENCODER_SPEC.md` に基づき、ピュアPython版(M1)に続いて、**Cythonによる高速化コアの実装 (M3)** および **実データコーパスを用いた評価 (M2)** が完了しました。目標性能を大きく上回る結果を達成しています。

## 行った変更

1. **Cython 高速化コア (M3) の実装**:
   - `_cython_mqcoder.pyx` を新規に作成し、算術符号化と画素コンテキスト生成ループを C言語レベルの静的型付け（`uint8_t`, `uint16_t` 等の配列アクセス）で書き直しました。
   - `api.py` を改修し、C拡張が利用可能な場合は自動的に Cython 版 (`MQEncoderC`) を呼び出し、不可能な場合は Python 版へフォールバックする構成にしました。
   - `pytest` による自動テストを通過し、Python版と bit-exact（全く同一のバイト出力）であることを保証しました。
2. **コーパスベンチマーク (M2) の実施**:
   - `C:\tmp\tmp0613` に格納されている実データの PDF から `pypdfium2` を用いて 300dpi グレースケール画像を抽出し、2値化後にエンコードを行うベンチマークスクリプト `benchmark_corpus.py` を実装しました。
   - 比較対象として、標準的な TIFF Group4 (G4) 圧縮のファイルサイズも同スクリプト内で計測しました。

## 評価結果と検証

実コーパスの先頭20ページ（A4サイズ相当: 約 2050x3025 px）を用いてベンチマークを実行した結果は以下の通りです。

### 1. 処理時間（パフォーマンス目標の達成）
- **目標**: 1コアあたり 300ms 以下
- **実績**: 平均 **約 103 ms / ページ**
- **結論**: M3 目標を極めて余裕を持って**クリア**しました。Python版で数秒〜十秒かかっていた処理を劇的に高速化しています。

### 2. 圧縮サイズ（G4との比較）
- **JBIG2 圧縮率**: 元データ(RAW)比で **約 26.4 倍**
- **G4 圧縮率**: 元データ(RAW)比で **約 17.1 倍**
- **サイズ比較**: JBIG2 は G4 圧縮に対して **約 64.9%** のファイルサイズ（約35%削減）を達成しました。
- **結論**: `template 0` によるベースラインの Generic Region 圧縮として、規格本来の強力な圧縮性能が発揮できていることが確認されました。

> [!TIP]  
> これにより、外部バイナリ (`jbig2enc` 等) に依存せず、高速かつ高圧縮なピュアPython/Cython拡張の JBIG2 エンコーダ `pyjbig2` の基盤が完成しました。次の段階（M4）では、HokusaiPress のパイプラインへ本格的に統合することが可能です。
