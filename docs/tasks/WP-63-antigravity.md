# WP-63 (Antigravity): /ingest 画面にドラッグ&ドロップ取込を追加

前提: WP-63a（`POST /api/upload`）完了済み。担当: Antigravity。
既存の `/ingest`（パス入力欄＋ジョブ一覧、`src/hokusai_press/webui/app.py` の
`ingest_view()`）はそのまま活かし、**ドロップゾーンを追加**する。

> Antigravity 向け注意: 下記以外の設計判断をしない。新エンドポイントは追加しない
> （`/api/upload` は実装済み）。外部ライブラリ・CDN・ビルド工程は導入しない。

## 作るもの
`ingest_view()` の HTML/JS に、既存の「サーバ上のファイルパス」入力の**上**に
ドラッグ&ドロップ領域を追加する:

1. **見た目**: 点線の角丸ボックス、中央に「ここにファイルをドラッグ、またはクリックして選択」
   の文言とアイコン（絵文字で可、例 📄）。クリックでファイル選択ダイアログも開く
   （非表示の `<input type="file">` をクリックで発火）。
2. **ドラッグ中のフィードバック**: `dragover` でボックスの枠色・背景を変える
   （既存の `--accent` 変数を使う）。`dragleave`/`drop` で元に戻す。
3. **アップロード処理**: ドロップ（または選択）されたファイルを
   `FormData` に詰めて `POST /api/upload`（`multipart/form-data`、
   `fetch` はそのまま `FormData` を渡せば Content-Type は自動設定される。
   手動でヘッダを付けない）。
   - 複数ファイルドロップ時は **順番に1つずつ** アップロードする（同時多重は避ける）。
   - 各ファイルのアップロード中はドロップゾーン内に進捗行（ファイル名＋状態）を出す。
   - 成功したら既存の `pollJobs()` を呼んでジョブ一覧を更新する
     （`ingest()` の成功時と同じ挙動に揃える）。
   - 失敗（4xx等）は既存の `errorMsg` 領域にエラーを表示する
     （`submitIngest()` のエラー表示と同じパターンを再利用）。
4. 既存の「サーバ上のパス」入力欄とボタンは**削除しない**。ドロップゾーンと共存させる
   （見出しで「ファイルをドロップ」と「またはサーバ上のパスを指定」を分けてよい）。

## 模倣する既存の流儀
- 同ファイル内の `submitIngest()`/`pollJobs()`/`escapeHtml()` のスタイルに合わせる
  （生 JS、`fetch`、`try/catch`、`errorMsg` 要素の使い回し）。
- CSS は既存の `<style>` ブロック内に追記する形で、`_shell()` が提供する
  共通スタイル変数（`--accent` 等）をそのまま使う。
