# WP-75 (Antigravity): ログイン画面・ナビのユーザー表示・管理者用ユーザー追加

家庭内サーバのマルチユーザー化・最終段。担当: Antigravity。
前提: WP-73（`POST /api/login`, `/api/setup`, `/api/logout`, `GET /api/me`,
`POST /api/users`, `GET /api/users`）, WP-74（所有権フィルタ）完了済み。

> Antigravity 向け注意: 下記以外の設計判断をしない。新しい API エンドポイントは
> 追加しない（全て実装済み）。外部ライブラリ・CDN・ビルド工程は導入しない。

## 背景（読んでおくこと）
`require_auth=True` のとき、未ログインで HTML ページにアクセスすると
`/login` へ 302 リダイレクトされる（`app.py` のミドルウェア、変更禁止）。
しかし **`/login` ルート自体がまだ存在しない**（404 になる）。今回それを作る。
また初回起動時はユーザーが1人もいないので `POST /api/setup` で最初の管理者を
作る導線が要る。

## 作るもの

### 1. `/login` ルート（新設、認証不要でアクセスできる必要がある）
- `_shell()` を使わない**素の HTML**（ナビバー無し。ログイン前なので書庫等への
  リンクは不要）。中央にカード、ユーザー名・パスワード入力欄、ログインボタン。
- 挙動:
  1. ページ読み込み時に `GET /api/users` を試す（管理者権限が無ければ 403 が
     返るのは想定内で無視してよい）。**別の方法でユーザーが1人もいないか判定**
     するのは複雑なので、代わりに次の単純な方式にする:
     フォームの下に小さく「初回セットアップの方はこちら」リンクを常に置き、
     クリックで「初期管理者を作成」フォーム（ユーザー名・パスワード）に切替え、
     送信で `POST /api/setup`。成功したら `/library` へリダイレクト。
     `/api/setup` が既にユーザーがいて `403` を返した場合は
     「既にセットアップ済みです。ログインしてください」とだけ表示してログイン
     フォームに戻す。
  2. 通常ログイン: ユーザー名・パスワードを `POST /api/login`。成功で
     `window.location.href = "/library"`。失敗（401）でエラーメッセージ表示
     （赤文字、`errorMsg` パターンは他画面と同じ流儀でよい）。
- ミドルウェアの許可リストは `/api/login`, `/api/setup` のみなので、
  `/login`（HTML ページ）自体は **`require_auth=True` でも保護対象外にする
  必要がある**。もし `/login` を開いた時点でリダイレクトループになる場合は、
  `app.py` のミドルウェアの許可リストに `"/login"` を追加してよい
  （このファイルの中で唯一、ミドルウェア本体に触れてよい変更。パス文字列を
  1つ集合に足すだけで、ロジックは変えない）。

### 2. ナビにユーザー表示・ログアウトを追加（`_shell()` を拡張）
- `_shell()` の呼び出し元は変更しない。`_shell()` の内部で
  `GET /api/me` 相当の情報が要るが、`_shell` は同期の文字列関数なので
  API 呼び出しはできない。代わりに **クライアント側 JS** で:
  ページ読み込み時に `fetch('/api/me')` し、成功したらナビバー右端に
  `👤 <username>` とログアウトボタンを追加表示する（`require_auth=False`
  運用では `/api/me` が無くても静かに失敗するだけでよい＝try/catch で握る）。
  ログアウトボタン押下で `POST /api/logout` → `/login` へ遷移。
  この JS は `_shell()` が返す HTML の共通スクリプト部分に追記する
  （全画面で自動的に効くようにする）。

### 3. 管理者用ユーザー管理画面 `/admin/users`（新設）
- `_shell()` を使う通常画面。`GET /api/users` でユーザー一覧
  （ユーザー名・ロール）をテーブル表示。403 が返ったら
  「管理者のみアクセスできます」とだけ表示する。
- 新規ユーザー追加フォーム（ユーザー名・パスワード・ロール選択
  admin/user）→ `POST /api/users`。成功したら一覧を再取得。
- ナビには追加しなくてよい（管理者は URL を直接開く運用でよい。
  スコープを広げない）。
