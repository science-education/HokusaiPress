# WP-62 (Antigravity): 登録→修整→閲覧を貫く UI 統合

計画: 登録(取込)→修整(レビュー)→閲覧(読書)を一続きの製品らしい UI にする。
担当: Antigravity。前提: WP-61a(`POST /api/ingest`, `GET /api/jobs`)完了済み。

> Antigravity 向け注意: 下記以外の設計判断をしない。API は全て実装済みで、
> 新しいエンドポイントを追加しない。JS フレームワーク・ビルド工程・外部 CDN を
> 導入しない（オフラインで動くこと）。既存の Python 文字列 HTML 方式を維持する。

## 作るもの

### 1. 共通シェル（全画面）
`app.py` 内に共通のヘッダ/スタイルを返すヘルパー関数（例 `_shell(title, body)`)を
1つ作り、下記4画面すべてで使う:
- 上部ナビバー: 「📚 書庫 (/library)」「📥 取込 (/ingest)」「✏️ レビュー (/)」の3リンク
  ＋現在ページのハイライト。
- 統一スタイル: システムフォント、白背景・濃灰文字、アクセント1色（例 #3b82f6）、
  カード風の枠（角丸+薄い影）、十分な余白。ダークモード不要。
- 適用先: `/library`, `/read/{doc_id}`, `/`（レビューキュー）, 新設 `/ingest`。
  `/page/...` は複雑なので**触らない**。

### 2. `/ingest` 画面（新設ルート1つ）
- サーバ上のファイルパスを入力するテキスト欄＋「取込開始」ボタン。
  送信で `POST /api/ingest` (body `{"path": ...}`)。400 ならエラーメッセージ表示。
- ジョブ一覧: `GET /api/jobs` を3秒間隔でポーリングし、
  running=回転スピナー/黄、done=緑チェック、error=赤+エラーメッセージ、を表示。
  done の行は「📖 読む (/read/{doc_id})」リンクを付ける。

### 3. `/library` の改装（ルートは既存のまま、HTML を差し替え）
- 書籍をカードグリッドで表示: タイトル（無ければ doc_id）、ページ数、
  「読む」ボタン。検索ボックスは上部に統合（挙動は現状どおり /api/search）。
- 検索ヒットは snippet の `[...]` 部分を `<mark>` でハイライトして表示
  （HTML エスケープしてから置換）。

### 4. `/`（レビューキュー）の改装（ルートは既存のまま、HTML を差し替え）
- `GET /api/queue` は rank_score 降順で返る。テーブルで表示:
  ページリンク（/page/{doc}/{i}）、doc_id、page_index、flags、
  rank_score（「この判断で解決が見込める類似ページ数」として表示）。
- 空なら「レビュー待ちはありません 🎉」。
